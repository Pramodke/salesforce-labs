API names must match exactly, because the Apex sets these fields by name. Create the object and fields before you deploy the component in Step 2.

2. Deploy the component with Workbench

The zip StudentOnboarding_Deploy_Workbench.zip contains the LWC, the Apex controller and test, and a permission set. It does not create the object, so make sure Step 1 is done first.

  1. Go to workbench.developerforce.com and log in to your org.
  2. migration, then Deploy. Choose the zip.
  3. Tick Single Package. Optionally tick Rollback On Error. Deploy.
  4. Assign the permission set Student Onboarding Access to yourself so you can run and test it internally.

3. Turn on email deliverability

Setup, Email, Deliverability. Set Access to Send Email to All email. Developer orgs block Apex email until you do this, so the confirmation would not arrive.

4. Create the public community (Digital Experience)

4a

Enable and create the site

  1. Setup, search Digital Experiences, Settings, tick Enable Digital Experiences. Accept the domain.
  2. All Sites, New. Choose the Customer Account Portal template. Get Started.
  3. Name it Student and set a URL such as student. Create.
  4. Open Builder (Experience Builder) for the site.
4b

Allow guests and add the page

  1. In Builder, Settings, General, tick Guest users can see and interact with the site without logging in.
  2. Pages menu, New Page, Standard Page, name it Student Tracker.
  3. Components panel, under Custom, drag studentOnboarding onto the page.

5. Style the page and make it public

  1. Theme (paint brush icon): use it to show or hide chrome. Open Theme / Layout settings and choose a clean layout. To show only your form, hide the header and navigation (Hide all).
  2. Open the page Page Settings (gear on the page), then Properties, then Page Access, and set it to Public.
  3. Publish the site (top right).
Optional: select the studentOnboarding component on the page and set its Full page URL property to this page URL, so the "Open in full page" button works on mobile.

6. Activate the site and grant guest access

  1. Setup, Digital Experiences, All Sites, your site, Administration, Activate. Copy the site URL.
  2. The page is reached by adding the site path, for example:
https://YOURDOMAIN.my.site.com/student/s/student-tracker

(The /s/ is the community page path. Use /s/ for the home page, or /s/student-tracker for this page.)

Guest access

The one thing the guest user needs

  1. In Builder, Settings, General, click the Guest User Profile link (or Setup, All Sites, Administration, Pages, Guest User Profile).
  2. Give the guest user Apex Class Access to OnboardingController, or assign the Student Onboarding Access permission set to the guest user.
That is all the guest needs. The Apex runs "without sharing", so it creates the Applicant, saves the files and sends the email in system context. The guest needs no object or field permissions. Do not try to give the guest Edit on the object, the guest license does not allow it.

7. Test end to end

  • Open the public URL in an incognito window (logged out). Allow the browser location prompt.
  • Fill the form, add at least one SSC file and one HSC file, tick consent, Submit.
  • You see the 3D loader, then the green "Application submitted" panel.
  • In Salesforce, the Applicant record exists with Status Submitted, the two files under Related, and the latitude and longitude filled.
  • A branded confirmation email arrives with all details and the documents attached (check spam).

What the component does

  • Two upload areas, SSC (10th) and HSC (12th), which stack on mobile. Each requires at least one file. Files are stored with an [SSC] or [HSC 12th] prefix.
  • Validation on the client and again in Apex: required fields, email format, 10 digit phone, 6 digit pincode, percentages 0 to 100, consent, allowed file types (PDF, JPG, PNG), 5 MB per file.
  • Location capture: the browser asks once for permission and stores Latitude and Longitude with the application.
  • Confirmation email with every submitted detail in a table and the documents attached.
  • 3D cube loader on page load and during submit, and a branded DY Patil header with a fresh colour theme.

Security

  • Guest least privilege: the guest gets only Apex class access. No object or field permissions, so a guest can never read or list applicants.
  • Server side validation: every rule is enforced again in Apex, so nothing bad gets in even by calling the API directly.
  • File safety: only PDF, JPG, PNG, and a 5 MB cap, checked in the browser and in Apex.
  • Consent is captured for data protection.
  • HTTPS everywhere, which also lets the browser share location.
  • Spam: turn on reCAPTCHA in Builder, Settings, Security for the public form.
  • Guest file attach: the code sets FirstPublishLocationId so the platform links the file, because guests cannot insert a ContentDocumentLink.

Troubleshooting (the real errors)

SymptomCause and fix
aura:systemError in the community, works internallyGuest user is missing Apex class access. Grant OnboardingController to the guest user profile, or assign the permission set to the guest.
INSUFFICIENT_ACCESS_ON_CROSS_REFERENCE_ENTITY, "permission to share this file"Guests cannot insert a ContentDocumentLink. The code fixes this by setting FirstPublishLocationId on the file. Make sure the deployed Apex is the latest.
Cannot assign permission set to guest, "Edit Applicants" not allowedGuest licenses do not allow Edit on custom objects. The permission set now grants only Apex class access, so it assigns cleanly.
No email receivedSet Deliverability to All email. Also check spam. Guest email can be limited, if the record saves but no email arrives, send the email from a record triggered Flow instead.
Please fill all required fields when all filledAn older build. The current build reads values at submit and names the exact missing field.
