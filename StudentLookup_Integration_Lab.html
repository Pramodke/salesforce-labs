1. Before you start and the files you have

  • A free Salesforce Developer org (developer.salesforce.com/signup).
  • A GitHub account, if you use the My JSON Server option in Step 1.
  • Workbench access (workbench.developerforce.com) if you deploy the component with a zip.

Data files shared with you, in this same folder:

2. Get the student data (the data URL)

Salesforce reads the results from a plain URL. Pick one of the two options.

Option A

mockapi.io (what this lab uses)

  1. Sign up at mockapi.io and create a New Project. When asked for the API Prefix, keep /api/v1.
  2. Create a resource named students. Add these fields, all type String: rollNo, firstName, lastName, email, phone, branch, year, semester, sgpa, cgpa, result, backlogs. mockapi adds its own id.
  3. Open the Data tab and edit a few rows so their rollNo values are known ones like CE2021001. On the free plan you edit rows by hand. On the paid plan you can import mockapi_students_import.json.
  4. Your base URL looks like this, where PROJECTID is shown at the top of your project:
https://PROJECTID.mockapi.io/api/v1/students

Filter by roll number (this is the URL the flow will call):

https://PROJECTID.mockapi.io/api/v1/students?rollNo=CE2021001

Open that in a browser first. It returns an array with one student.

Option B

My JSON Server on GitHub (free, no signup)

  1. Put db.json at the root of a public GitHub repo, for example a repo named MockData, on the main branch. The file name must be exactly db.json.
  2. Your live API is instantly available. Base URL:
https://my-json-server.typicode.com/YOURUSER/MockData/students

Filter by roll number:

https://my-json-server.typicode.com/YOURUSER/MockData/students?rollNo=CE2021001

Single record, because id equals the roll number in db.json:

https://my-json-server.typicode.com/YOURUSER/MockData/students/CE2021001
Size limit: My JSON Server only serves a db.json up to about 10 KB, which is why db.json holds 25 students, not 200. For all 200, host students_mock_data.json on raw GitHub instead, but note raw GitHub cannot filter, so the flow would fetch all and match inside the loop.
Remember the split for the flow later: the Named Credential URL is the base up to and including the prefix, for example https://PROJECTID.mockapi.io/api/v1. The callout Path is /students. The query parameter is rollNo.

3. Create the External Credential

Setup, then Named Credentials, then the External Credentials tab, then New.

  • Label and Name: MockAPI_Auth.
  • Authentication Protocol: No Authentication if available, otherwise Custom. Both are fine because the API is public.
  • Save, then add a Principal named Anon, Identity Type Named Principal.

4. Create the Named Credential

Same page, Named Credentials tab, New.

  • Label and Name: StudentAPI.
  • URL: your base URL, for example https://PROJECTID.mockapi.io/api/v1.
  • External Credential: select MockAPI_Auth. Save.

5. Grant your user access to the credential

This step is easy to miss, and the callout fails silently without it.

  • Setup, Permission Sets, New: Student API Access.
  • Open it, External Credential Principal Access, Edit, add MockAPI_Auth - Anon, Save.
  • Manage Assignments, Add Assignment, select yourself, Assign.

6. Create the HTTP Callout (External Service)

Setup, External Services, New External Service, then From HTTP Callout.

  • Service name: StudentService. Named Credential: StudentAPI.
  • Add an operation: Method GET, Path /students, add a Query Parameter named rollNo.
  • Provide a sample response. Copy the real output from your browser, or paste this array with one student:
[
  {
    "id": "1",
    "rollNo": "CE2021001",
    "firstName": "Manish",
    "lastName": "Patil",
    "email": "manish.patil1@dyptc.edu.in",
    "phone": "9150017772",
    "branch": "Computer Engineering",
    "year": "Second Year",
    "semester": "4",
    "sgpa": "7.51",
    "cgpa": "7.98",
    "result": "PASS",
    "backlogs": "0"
  }
]

Save. The response is an array, so Salesforce generates a collection you can loop over in the flow.

7. Deploy the display component (LWC)

Flow text cannot show a background or a real card, so a small component gives the professional look. Deploy it in one of two ways.

6a

Deploy with Workbench (using the zip)

  1. Go to workbench.developerforce.com and log in to your org.
  2. migration, then Deploy.
  3. Choose StudentUI_Deploy_Workbench.zip.
  4. Tick Single Package. Optionally tick Rollback On Error.
  5. Next, then Deploy. The zip contains package.xml at the root, the component, and the flow.
Notes: the package.xml version is 67.0, which supports the flow. The dependencies (your External Service and Named Credential) already exist in the org, so they are not in the package. If Workbench reports it cannot deploy an active flow, enable Setup, Process Automation Settings, Deploy processes and flows as active, or change the flow status to Draft in the file and activate it after deploy.
6b

Or paste it in Code Builder

8. Build the Screen Flow

If you deployed the zip, the finished flow is already there. To build it by hand:

Flow

Screen, action, loop, decision, card

  1. Search screen: a Display Text title, and a Text input named rollNoInput, marked required.
  2. Action, the HTTP Callout: set the query parameter rollNo to {!rollNoInput}. For case safety, use a formula UPPER({!rollNoInput}) instead.
  3. Loop: Collection Variable is the callout output {!StudentService.2XX}. The loop item is currentStudent. The list has zero or one student, so it runs at most once.
  4. Assignment inside the loop, capture every field: 
    vRollNo    = {!currentStudent.rollNo}
vFirstName = {!currentStudent.firstName}
vLastName  = {!currentStudent.lastName}
vEmail     = {!currentStudent.email}
vPhone     = {!currentStudent.phone}
vBranch    = {!currentStudent.branch}
vYear      = {!currentStudent.year}
vSemester  = {!currentStudent.semester}
vSgpa      = {!currentStudent.sgpa}
vCgpa      = {!currentStudent.cgpa}
vResult    = {!currentStudent.result}
vBacklogs  = {!currentStudent.backlogs}
isFound    = true
    Create each of these as Text variables first, plus a Boolean isFound.
  5. Decision after the loop: if isFound is true go to the result screen, otherwise a not found screen.
  6. Result screen: place the studentResultCard component and map each input to the matching variable, for example firstName to {!vFirstName}, result to {!vResult}, and so on for all twelve. You now see the styled card with every field.
  7. Not found screen: a friendly message such as No student found for {!rollNoInput}.
Why the loop, and why not an index: a filter always returns a list, even for one match. Flow has no way to read item number one, there is no 2XX[0] in Flow, so the loop lifts the record into variables. Friendly element labels help too: Initialize State, Loop Students, Capture Student Fields, Is Data Found, Result Card. The kit flow already uses these labels.

9. Create a Tab

Most teams skip a standalone tab and place the flow on a Lightning App Page, then add that page to an App, which is Step 9. If you do want a dedicated tab, Setup, Tabs, create a Lightning page tab that points to the App Page you build next.

10. Create an App and place the flow

  • Setup, Lightning App Builder, New, App Page, one region layout. Name it Student Lookup. Drag the Flow component on and choose your flow. Save and Activate, adding it to an app or as a tab during activation.
  • Setup, App Manager, New Lightning App. Name it Campus Services, pick a colour and icon. On Navigation Items add your Student Lookup page. Assign it to the right profiles. Save and Finish.
  • Open the App Launcher, choose Campus Services, and use it.

11. Test end to end

  • Open the app, type CE2021001, and the styled card appears with a PASS or FAIL badge and every field.
  • Type a roll number that has backlogs to see the red FAIL badge.
  • Type a made up roll number to see the not found screen.
  • If nothing returns, open the callout URL in a browser and confirm the roll number exists and the case matches.

12. The purpose of each Named Credential item

ItemWhat it holdsWhy it exists
External CredentialHow to authenticate: the protocol and the principal.Separates how you log in from where you call, so it can be reused.
Principal (Anon)The identity used on the call. Anonymous here.For a secured API this is where the key or token lives, encrypted.
Named CredentialThe base URL, linked to the External Credential.Keeps the endpoint out of the flow. Change it in one place.
Permission Set accessPermission for a user to use the credential.Access control. Only granted users can make the call.
HTTP Callout in the flowThe path, method, and parameters.The actual request. It refers to the credential by name, never the raw URL.

13. Security in this design

  • No secret in the flow. The URL sits in the Named Credential, any key sits encrypted in the External Credential.
  • Access is granted, not assumed. Only users with the permission set can run the callout.
  • HTTPS everywhere. The callout is encrypted in transit by default.
  • Show only what is needed. Display the fields the task requires and keep sensitive data off the screen.
  • Rotate in one place. If a key changes, update the External Credential once, not every flow.
  • Mock data only. This lab uses fabricated students. Never put real results on a public mock host. For real records use an authenticated API and fetch only what you need.

14. Troubleshooting the real errors

SymptomCause and fix
Workbench: No package.xml foundTick the Single Package checkbox. It must be on for a zip that has package.xml at the root.
Property areMetricsLoggedToDataCloud not valid in version 62.0The manifest version is too low. Set package.xml version to 67.0, which the kit already does.
InterpretedConnectivityDisabled or a missing label errorUse a new style Named Credential with an External Credential, deploy My Domain, and grant the permission set access.
Loop Collection Variable is emptyThe response could not be read as a collection. Re-paste the sample with the square brackets, or use a wrapped object with a students list.
Display shows the merge text, not a valueYou used an index like 2XX[0]. Flow has no index. Loop and use the loop item or the variables you assigned.
Cannot deploy an active flowEnable Deploy processes and flows as active in Process Automation Settings, or set the flow status to Draft and activate after deploy.
Filter returns an empty arrayThe roll number is case sensitive on the mock host. Type it exactly, or use UPPER in a formula.
Query on the root returns nothingAdd the resource name. Use /students?rollNo, not the base URL by itself.
